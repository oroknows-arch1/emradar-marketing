# Human correspondence v2

The evidence/editorial worker decides what the current sources support. The existing
`human_ready_email` graph node renders that proposition as Sean Walker's complete
person-to-person correspondence, before the capability gate and exact publication
review. No new graph node, provider call, infrastructure or sending route is added.

For fresh email propositions, the existing editorial worker and independent verifier
must produce and verify `correspondence.reason/development/insight/proposition/question`.
Each part appears in the evidence-qualified body. The reason names the actual
publication and derives from its verified beat; the insight explains what stood out.
Body text is at most 180 words and must fit the recipient's full email word limit,
including introduction, greeting, supporting link and sign-off. No source URLs,
evidence headings, anonymous institutional opening or generic relevance claim belong
in that proposition. The existing editorial context includes these requirements and
requires `editorial_checks.human_correspondence=PASS` as well as all prior checks.

The bounded renderer adds a contact-bound verified name or neutral greeting, a short
human introduction, one supporting source, and Sean Walker / EMRADAR sign-off.
Campaign-specific language comes from the verified proposition, not a fixed template.
Introductions have stable natural variations so review and delivery remain identical.
Chilean Spanish is composed in the original editorial work and wrapped in native
professional Spanish. Other language profiles block until supported.

`oroknows@gmail.com` remains the only authenticated account; it is separate from the
human name. The Gmail adapter and existing Starter relay accept the exact reviewed
Sean Walker envelope and do not rewrite it. The renderer and capability gate allow
only the presently included source-linked note, with a complete verified capability
inventory. No future article, research, interview, visual or monitoring offer is
inferred. Omission of a next step is valid when no supported offer fits.

Source state, full internal evidence, every source uncertainty and source revision
remain bound. Historical sent proposals and receipts are never migrated or resent.
Legacy unsent revision remains explicitly restricted to its original source/route
and review gate. V1 unsent mail needs fresh exact review rather than hidden rewriting.

Communication features are inside the hashed email artifact and publication review:
greeting type, named recipient, introduction style/variant, specific contact reason,
angle, email length, question type/text, offered next step, language and revision.
Outcome normalization and analysis retain these with receipt/artifact references,
observed outcome and sample size. Historical missing features remain null. One reply
never establishes a style rule or a causal claim; existing evidence thresholds remain.

`correspondenceProbe` is a pure test-only historical Sierra Gorda regression. It calls
the actual renderer/capability validator, logs a runtime artifact hash and does not
fetch a scan, admit a campaign, write state or distribute anything.


Recipient agency is required: correspondence.question asks whether or how the
material, note, angle or contribution would help this recipient, letting them
choose a useful destination-native form. A subject-matter question is insufficient.
Generate destination-appropriate wording; never append a fixed closing sentence.
The independent human_correspondence verifier must check this semantic function.
